================================================================================
  DATABASE SCHEMA ASSUMPTIONS
================================================================================

The SQL queries in slack_integration_example.py assume these tables:

analytics_events:
  • event_type (TEXT): 'open' or 'click'
  • email_open_id (INT): unique identifier
  • email_click_id (INT): unique identifier
  • created_at (DATETIME): timestamp

deals:
  • id (INT): primary key
  • company_name (TEXT): company name
  • amount_usd (FLOAT): deal amount
  • status (TEXT): 'CLOSED', 'ACTIVE', etc.
  • closed_at (DATETIME): when deal closed
  • service_type (TEXT): 'audit', 'drone', etc.
  • closer_name (TEXT): who closed the deal

leads:
  • id (INT): primary key
  • company_name (TEXT): company name
  • status (TEXT): 'ACTIVE', 'QUALIFIED', etc.
  • estimated_value_usd (FLOAT): quote/estimate
  • created_at (DATETIME): when lead added

expenses:
  • id (INT): primary key
  • amount_usd (FLOAT): expense amount
  • created_at (DATETIME): when incurred

If your schema differs, copy the SQL from slack_integration_example.py and
adapt table/column names. Same logic, different names.

================================================================================
  STATUS THRESHOLD MAPPING
================================================================================

All templates use 4-tier status system:

  ON_TRACK   🟢  Achievement % >= 100%
  BEHIND     🟡  Achievement % 85-99%
  ALERT      🟠  Achievement % 70-84%
  CRITICAL   🔴  Achievement % < 70%

Achievement % = (actual / target) × 100

Example:
  • Sales target: 2 deals
  • Actual: 2 deals
  • 2/2 = 100% = ON_TRACK 🟢

  • Sales target: 2 deals
  • Actual: 1.5 deals
  • 1.5/2 = 75% = ALERT 🟠

================================================================================
  GITHUB ACTIONS SETUP (3 MINUTES)
================================================================================

Create: .github/workflows/daily-slack-updates.yml

Paste (from SLACK_DAILY_TEMPLATES_GUIDE.md → GitHub Actions section):
  name: Daily Slack Updates
  on:
    schedule:
      - cron: '0 8 * * *'    # 8 AM UTC
      - cron: '0 18 * * *'   # 6 PM UTC
      - cron: '0 10 * * 0'   # 10 AM UTC Sunday
      - cron: '0 0 1 * *'    # 12 AM UTC 1st of month
  jobs:
    daily-updates:
      runs-on: ubuntu-latest
      steps:
        - uses: actions/checkout@v4
        - uses: actions/setup-python@v4
          with:
            python-version: '3.11'
        - run: pip install aiohttp
        - run: python pipeline/slack_integration_example.py all
          env:
            SLACK_BOT_TOKEN: ${{ secrets.SLACK_BOT_TOKEN }}
            SLACK_REVENUE_CHANNEL: C0B8VN2S89Y

Then:
  1. Add SLACK_BOT_TOKEN to GitHub Secrets
  2. Push to main branch
  3. Go to Actions → Workflows → "Daily Slack Updates"
  4. Watch for first run at 8 AM UTC (or trigger manually for testing)

================================================================================
  TROUBLESHOOTING
================================================================================

Problem: "No message in Slack after waiting"
  1. Check SLACK_BOT_TOKEN is set: echo $SLACK_BOT_TOKEN
  2. Check bot has "chat:write" permission in Slack workspace
  3. Check SLACK_REVENUE_CHANNEL is correct: should be C0B8VN2S89Y or your ID
  4. Check GitHub Actions workflow ran: go to Actions tab
  5. Check GitHub Actions logs for errors
  6. Test locally: python pipeline/slack_daily_templates.py

Problem: "Database query returns no results"
  1. Check database exists: ls -la production_mesh_edge.db
  2. Check database path: export MESH_DB_PATH="/full/path/to/db.db"
  3. Check table names match your schema
  4. Check date ranges in queries (24h, 7d, 30d)
  5. Run query manually: sqlite3 production_mesh_edge.db "SELECT COUNT(*) FROM deals"

Problem: "Metrics show 0 or None"
  1. Check date/time handling (timezone aware?)
  2. Check SQL column names vs template field names
  3. Check COALESCE() in queries for NULL handling
  4. Test with sample data first: insert test rows into DB

Problem: "Message formatting looks wrong"
  1. Check Slack workspace theme (light/dark mode)
  2. Verify emoji support (Settings → Emoji → enabled)
  3. Check Block Kit format in python file (header, section, fields, divider)
  4. Test in Slack Block Kit Playground: app.slack.com/block-kit-builder
