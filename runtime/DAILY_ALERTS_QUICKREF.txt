QUICK START (5 minutes)
================================================================================

1. Copy template:
   cp daily_alerts.env.example .env

2. Edit .env with real values:
   EMAIL_PROVIDER=gmail
   GMAIL_USER=your-gmail@gmail.com
   GMAIL_APP_PASSWORD=xxxx xxxx xxxx xxxx     [from Google]
   ALERT_EMAIL=dispatch@alreadyherellc.com   [NO PLACEHOLDERS!]
   CLIENTS_DB_PATH=clients.db

3. Test:
   python3 daily_alerts.py --dry-run --verbose

4. Send test alert:
   python3 daily_alerts.py --verbose

5. Schedule (pick one):

   OPTION A - Cron (Linux):
   ----------------------
   crontab -e
   # Add: 0 23 * * * cd /home/opc/profitengine/runtime && /usr/bin/python3 daily_alerts.py >> daily_alerts.log 2>&1

   OPTION B - Systemd (Linux, preferred):
   -------------------------------------
   sudo cp daily_alerts.service /etc/systemd/system/
   sudo cp daily_alerts.timer /etc/systemd/system/
   sudo systemctl daemon-reload
   sudo systemctl enable daily_alerts.timer
   sudo systemctl start daily_alerts.timer
   sudo systemctl status daily_alerts.timer


EMAIL PROVIDERS
================================================================================

GMAIL (Recommended - Easiest):
  1. Enable 2-factor auth on Gmail
  2. Get app password: https://myaccount.google.com/apppasswords
  3. Set in .env:
     EMAIL_PROVIDER=gmail
     GMAIL_USER=your-email@gmail.com
     GMAIL_APP_PASSWORD=xxxx xxxx xxxx xxxx

SENDGRID (High Volume):
  1. Create account at sendgrid.com
  2. Create API key with "Mail Send" permission
  3. Set in .env:
     EMAIL_PROVIDER=sendgrid
     SENDGRID_API_KEY=SG.xxx...

AWS SES (Enterprise):
  1. Verify domain/email in SES console
  2. Create IAM user with SES SendEmail permission
  3. Get access key & secret
  4. Set in .env:
     EMAIL_PROVIDER=aws_ses
     AWS_ACCESS_KEY_ID=AKIA...
     AWS_SECRET_ACCESS_KEY=...
     AWS_SES_REGION=us-east-1


OPTIONAL: TELEGRAM & SLACK
================================================================================

TELEGRAM:
  1. Create bot: @BotFather on Telegram
  2. Get chat ID: curl https://api.telegram.org/bot<TOKEN>/getUpdates
  3. Set in .env:
     TELEGRAM_BOT_TOKEN=123456:ABC-DEF...
     TELEGRAM_CHAT_ID=123456789

SLACK:
  1. Create webhook: https://api.slack.com/messaging/webhooks
  2. Copy webhook URL
  3. Set in .env:
     SLACK_WEBHOOK_URL=https://hooks.slack.com/services/...

TROUBLESHOOTING
================================================================================

Alert not sending:
  1. Verify .env exists: ls -la .env
  2. Check email credentials: python3 daily_alerts.py --verbose
  3. View logs: tail -50 daily_alerts.log | grep ERROR
  4. Verify scheduler is running:
     crontab -l           (for cron)
     systemctl list-timers (for systemd)

Gmail error "5.7.8 Username and password not accepted":
  1. Verify 2-factor auth is ON
  2. Get new app password: https://myaccount.google.com/apppasswords
  3. Use EXACT 16-char password (with or without spaces both work)
  4. Test: python3 daily_alerts.py --verbose

Database errors "database is locked":
  1. Close other connections to clients.db
  2. Check file permissions: ls -la clients.db
  3. Verify path is correct: echo $CLIENTS_DB_PATH

Scheduler not running:
  Cron:
    sudo journalctl -u cron
    grep CRON /var/log/syslog

  Systemd:
    sudo systemctl enable daily_alerts.timer
    sudo systemctl start daily_alerts.timer
    sudo journalctl -u daily_alerts.timer -f
