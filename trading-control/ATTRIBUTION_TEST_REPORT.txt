KNOWN ISSUES & RECOMMENDATIONS
================================================================================

ISSUE 1: P&L Decomposition Weighting Bug (CRITICAL)
--------
Location: performance_attribution.py, analyze_trade_contribution() method
         Lines 178-198

Problem:
  The weighting algorithm multiplies confidence-normalized weights by target
  percentages (0.35, 0.25, 0.25, 0.15), causing the sum of agent contributions
  to equal only ~25% of realized P&L instead of 100%.

  Example:
    - Technical confidence: 0.8, Microstructure: 0.6, Regime: 0.9, Portfolio: 0.7
    - Total confidence: 3.0
    - Technical weight: (0.8/3.0) * 0.35 = 0.0933
    - Sum of all weights: 0.2533 (should be 1.0)

Impact: Moderate
  - All agent statistics calculations work correctly despite this
  - The reported contributions are consistent but underrepresent actual attribution
  - This affects interpretation of "which agent contributed how much" to overall P&L

Fix Required:
  Option A (Recommended): Normalize by confidence only for weight distribution
    weights = [
        technical_conf / total_confidence,
        micro_conf / total_confidence,
        regime_conf / total_confidence,
        portfolio_conf / total_confidence
    ]
    # Then apply percentages only to reporting, not decomposition

  Option B: Use fixed percentages without confidence weighting
    if confidence_threshold > some_level:
        weights = [0.35, 0.25, 0.25, 0.15]
    else:
        weights = equal_weights_or_default

ISSUE 2: Consistency Score Calculation (MINOR)
--------
The consistency_score is calculated as 1.0/(1.0 + std_dev), which gives values
close to 0 even for good consistency. Consider using a more intuitive metric like
Sharpe ratio or correlation stability.
