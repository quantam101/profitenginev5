AUTOMATION SCHEDULE
================================================================================

HOURLY (Top of Every Hour: 00:00, 01:00, 02:00 ... 23:00 UTC)
  Trigger: GitHub Actions schedule
  Job: hourly-check
  Action: Fetch Gumroad API -> Log to JSON
  Duration: ~10 seconds
  Result: daily_revenue_YYYY-MM-DD.json (24-hour totals)

DAILY (09:00 UTC)
  Trigger: GitHub Actions schedule
  Jobs: daily-aggregation, email-summary, slack-notification
  Action:
    1. Fetch all 6 major APIs in parallel
    2. Aggregate data
    3. Calculate consolidated metrics
    4. Generate JSON report
    5. Generate markdown summary
    6. Send email via SendGrid
    7. Post to Slack webhook
    8. Auto-commit to git
  Duration: ~30 seconds
  Results:
    * daily_revenue_YYYY-MM-DD.json
    * DAILY_REVENUE_REPORT.md
    * Email notification
    * Slack notification
    * Git commit

API ENDPOINT MAPPING
================================================================================

GUMROAD:
  Endpoint: GET https://api.gumroad.com/v2/products
  Auth: Bearer token
  Frequency: Hourly + Daily
  Extract: sales_in_last_24_hours, revenue_in_last_24_hours
  Template: Section 1

STRIPE:
  Endpoint: GET https://api.stripe.com/v1/charges
  Auth: Bearer token
  Frequency: Daily
  Filter: created[gte]=24h_ago, status=succeeded
  Extract: amount (convert cents to dollars)
  Template: Section 2

YOUTUBE:
  Endpoint: GET https://www.googleapis.com/youtube/v3/channels
  Endpoint: GET https://youtubeanalytics.googleapis.com/v2/reports
  Auth: OAuth 2.0
  Frequency: Daily
  Extract: views, watch_time, subscribers_gained, revenue
  Template: Section 5

EMAIL PLATFORM (e.g., Mailchimp v3):
  Endpoint: GET https://us1.api.mailchimp.com/3.0/lists
  Auth: API key
  Frequency: Daily
  Extract: subscriber count, growth rate, campaign stats
  Template: Section 2

AFFILIATE NETWORKS (e.g., ShareASale):
  Endpoint: GET https://api.shareasale.com/x/api/stats
  Auth: API key + token
  Frequency: Daily
  Extract: clicks, conversions, revenue
  Template: Section 4

TRADING (e.g., Robinhood API):
  Endpoint: Account API endpoints (varies)
  Auth: OAuth token
  Frequency: Daily
  Extract: portfolio_value, daily_pnl, positions
  Template: Section 8

================================================================================
ERROR HANDLING STRATEGY
================================================================================

API ERROR (4xx, 5xx response):
  1. Log error to errors array
  2. Skip this API call
  3. Continue with other APIs
  4. Report error in daily summary
  5. Alert via email/Slack

MISSING CREDENTIAL:
  1. Check for API key in secrets
  2. If missing, log "not configured"
  3. Skip this data source
  4. Continue with others
  5. Report missing in daily summary

NETWORK TIMEOUT (> 10 seconds):
  1. Catch timeout exception
  2. Log error
  3. Skip this API
  4. Move to next
  5. Report timeout in summary

ALL SOURCES FAILED:
  1. Generate report with empty data
  2. Include all error messages
  3. Send alert email
  4. Post warning to Slack
  5. Git commit with error log

GRACEFUL DEGRADATION:
  * Report includes all data sources that succeeded
  * Failed sources shown as empty in report
  * System continues even with partial data
  * User can manually add missing metrics

================================================================================
SECURITY MODEL
================================================================================

CREDENTIAL STORAGE:
  Location: GitHub Secrets (encrypted at rest)
  Access: GitHub Actions runners only
  Key Rotation: Manual (update secret, re-run workflow)
  Logging: API keys never logged or printed
  Backup: GitHub handles encryption

CREDENTIAL USAGE:
  GitHub Actions retrieves secrets
  Scripts read from environment variables
  Scripts use credentials to call APIs
  Scripts never write credentials to disk
  Credentials deleted when process ends

DATA PROTECTION:
  API responses: Temporarily in memory
  Generated reports: Stored in artifacts (90 days)
  Git history: Permanent, contains no credentials
  Manual entries: Plain text, include only aggregate numbers
  No PII or sensitive data in reports

ACCESS CONTROL:
  GitHub repo admin access required
  Workflow execution: GitHub Actions only
  Manual trigger: Repo member only
  Secrets modification: Admin only
  Git push: Branch protection (main branch)

RECOVERY & BACKUP
================================================================================

AUTOMATIC BACKUPS:
  * Git commits: Daily (includes daily_revenue_*.json)
  * GitHub artifacts: 90-day retention
  * Workflow logs: Available for 90 days

MANUAL BACKUPS:
  * Monthly archives: User creates /archives/YYYY-MM/
  * Quarterly exports: User downloads for analysis
  * Offline copies: User maintains local backup

RECOVERY PROCEDURE:
  If daily report missing:
    1. Check GitHub Actions > daily_revenue_tracking > Latest run
    2. Review Logs tab for errors
    3. Check Artifacts tab for daily_revenue_*.json
    4. If still missing, manually re-run workflow
    5. Fallback: Use DAILY_REVENUE_TRACKING_TEMPLATE.md

  If API credentials lost:
    1. Regenerate API keys on each platform
    2. Update GitHub Secrets with new values
    3. Re-run workflow
    4. Verify report generation

  If workflow broken:
    1. Check .github/workflows/daily_revenue_tracking.yml syntax
    2. Review GitHub Actions error logs
    3. Test scripts/daily_revenue_tracker.py locally
    4. Fix and push to main branch

================================================================================
TROUBLESHOOTING DECISION TREE
================================================================================

PROBLEM: No report generated

  Is GitHub Actions enabled?
    NO -> Enable workflow in .github/workflows/daily_revenue_tracking.yml
    YES -> Continue

  Check GitHub Actions log
    Is workflow syntax error?
      YES -> Fix YAML syntax, push to main
      NO -> Continue

    Are secrets configured?
      NO -> Add all 8 secrets to GitHub Settings
      YES -> Continue

    Is at least one API responding?
      NO -> Check internet connection, API status pages
      YES -> Continue

  Check for error messages in log
    API timeout error?
      -> Check API status
      -> Try manual run again
    Missing secret?
      -> Add to GitHub Secrets
    Permission denied?
      -> Check API credentials
    Network error?
      -> Check firewall, proxy settings

PROBLEM: Some metrics missing

  Is API key correct?
    NO -> Regenerate API key, update secret
    YES -> Continue

  Does API key have required permissions?
    NO -> Update API key scope/permissions
    YES -> Continue

  Is API rate limit hit?
    NO -> Continue
    YES -> Reduce frequency or upgrade tier

  Is API documentation current?
    NO -> Check for API deprecation
    YES -> Continue

PROBLEM: Email not sending

  Is SENDGRID_API_KEY configured?
    NO -> Add to GitHub Secrets
    YES -> Continue

  Is SendGrid account active?
    NO -> Reactivate SendGrid account
    YES -> Continue

  Is email address valid?
    NO -> Update DAILY_TRACKING_EMAIL secret
    YES -> Continue

  Check SendGrid logs for delivery errors
    Rate limited?
      -> Wait, retry later
    Invalid recipient?
      -> Update email address
    API error?
      -> Check SendGrid status page

PROBLEM: Slack notification not received

  Is SLACK_WEBHOOK_REVENUE_ALERTS configured?
    NO -> Add to GitHub Secrets
    YES -> Continue

  Is webhook URL valid?
    NO -> Regenerate webhook in Slack workspace
    YES -> Continue

  Is Slack workspace active?
    NO -> Reactivate workspace
    YES -> Continue

  Test webhook manually
    URL working?
      NO -> Check firewall, proxy
      YES -> Continue

  Check GitHub Actions log for errors
    Rate limited?
      -> Wait, retry later
    Auth error?
      -> Regenerate webhook
    Network error?
      -> Check connectivity
